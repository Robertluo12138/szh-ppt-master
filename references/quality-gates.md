# Quality Gates

The gates a deck must pass before the skill reports success. Each gate maps to an explicit stage; if a gate is unimplemented today, that is recorded.

| Gate | Stage | Status |
|---|---|---|
| `source_manifest.bridge` — when `source_manifest.json` is present in the workspace, it must be a **regular in-workspace file**: a symlink at that path (broken or resolvable) is refused outright by an explicit symlink preflight that runs BEFORE `_try_load` / `read_text`, so neither a dangling link silently demoting the workspace to the legacy "no manifest" no-op (Path.is_file() returns False for a dangling target, indistinguishable from a missing file) nor a resolvable link reading manifest bytes from outside the workspace can slip through. The manifest then validates against `schemas/source_manifest.schema.json`; `source.local_path` (enum-locked to `input/source.md`) resolves inside the workspace and exists as a regular file (symlinks at the source file are refused too); the file is valid UTF-8; `source.byte_count` / `line_count` / `sha256` match the on-disk source; and `source.kind` is one of the schema-documented values (`markdown` for a .md-original source, `text` for a .txt-original source — `init_workspace.py` normalizes the on-disk filename to `input/source.md` regardless of the original extension, so both kinds are legitimate). When `deck_brief.json` is present in the same workspace, `deck_brief.source_refs` must include `source_manifest.source.id`. A Stage-1-only workspace (manifest + source.md present, `deck_brief.json` absent) is valid by design: the bridge passes every on-disk row and skips the deck_brief cross-check row rather than emitting a FAIL. Workspaces without `source_manifest.json` are a no-op (existing prepared examples that pre-date `init_workspace.py` remain valid). Tempfixture negatives also cover malformed (non-JSON) and list-rooted manifests as structured loadability / shape FAILs without traceback, and the symlink preflight for both a broken and a resolvable manifest symlink (the dangling target is never created; the resolvable target's bytes are preserved byte-identical and no schema-validate row is emitted because the preflight short-circuits before schema validation runs) | Intake → Brief | scaffold + workspace (`check_source_manifest_bridge` + tempfixture `negative_source_manifest_bridge_tempfixture_checks`) |
| `brief.bridge.helper` — `scripts/init_deck_brief.py` produces a minimal, schema-valid `deck_brief.json` from an already-stage-1-initialized workspace (`source_manifest.json` + `input/source.md`) plus the explicit user-supplied metadata flags (`--title` / `--audience` / `--objective`; optional `--tone` / `--language` / `--approximate-slide-count`). The helper does NOT extract business content from the source body, does NOT invent optional fields the caller did not pass, and does NOT produce any artifact other than `deck_brief.json`. Pre-conditions are enforced by reusing `check_source_manifest_bridge` (so a missing / malformed / sha-mismatched manifest, a missing or wrong-bytes `input/source.md`, or a brief that omits the manifest's `source.id` all fail closed). `source_manifest.json` must be a **regular in-workspace file**: a symlink at that path (broken or resolvable) is refused by an explicit symlink preflight inside the helper that runs BEFORE the is_file check and BEFORE `check_source_manifest_bridge` / `read_text`, so neither a dangling link masquerading as the legacy missing-manifest case nor a resolvable link reading manifest bytes from outside the workspace can slip through; in both cases the helper exits non-zero and no `deck_brief.json` is written. A pre-existing `deck_brief.json` is refused: a **symlink** (broken or resolvable) at that path is rejected outright by an explicit symlink-first guard that runs BEFORE the regular file-existence check, so `write_text()` cannot silently follow a dangling link and clobber whatever the link names (`Path.exists()` returns False for a broken symlink, so a bare existence gate would otherwise let that happen — same anti-pattern `run_pipeline.py` forbids at `--output` / `--report-dir`); a regular file at the same path is refused with the same "no overwrite" rule. `source_refs` is exactly `[source_manifest.source.id]`. The brief is schema-validated in memory before any write and re-validated on disk afterwards; a post-write re-validation failure (returning errors OR raising) rolls the brief back so the workspace returns to its pre-call state. The catch clause is `(Exception, SystemExit)` so `validate_artifact`'s `SystemExit` branch on read-errors still routes through rollback | Brief | `scripts/init_deck_brief.py --self-test` (29 in-script tempfixture scenarios) |
| `image_manifest.d_one_adapter_stub` — `scripts/done_image_adapter.py` is the **D-One adapter contract STUB** (not D-One integration). Given a workspace that already ships a schema-valid `image_manifest.json` plus a caller-supplied `--spec <prompt-spec.json>` whose top-level `requests[]` carries one entry per asset the caller wants D-One to generate (each entry: required `id` matching an `images[].id` whose `source == "d_one_local"` and non-empty `prompt`; optional `intended_use` / `width_px` / `height_px`), the helper validates the manifest, validates the spec, scans every prompt against a defense-in-depth deny list, and writes a deterministic dry-run plan file. The helper does NOT call D-One / Qoder / any image-generation model / any public network / any external service; does NOT generate any image bytes (PNG / JPG / JPEG / SVG / GIF / WebP); does NOT mutate `image_manifest.json` (manifest bytes must be byte-identical before and after a successful run); does NOT open `input/source.md` for content extraction (only its raw bytes, only for the 40-character shingle check); does NOT generate full-slide screenshots; does NOT produce `render_models/*` / `svg_previews/*` / any `.pptx`; and does NOT change PPTX export behavior. Fail-closed gates: `--workspace` and `--spec` URI-shape refused at the string layer before any filesystem call (so a URI-shaped `--spec` is refused even when `--workspace` happens to fail an earlier filesystem gate); `--workspace` not a symlink, existing directory; `--spec` not a symlink, existing regular file, parses as JSON, decodes to an object, no top-level keys other than `requests`; `requests[]` non-empty list of objects with required keys `id` (non-empty string) and `prompt` (non-empty string), optional keys `intended_use` (non-empty string) / `width_px` (positive int) / `height_px` (positive int), no extra keys, no duplicate `id`s; every `requests[].id` matches an `images[].id` in the manifest whose `source == "d_one_local"` (`local_asset` / `synthetic` entries are refused outright so a caller cannot smuggle a non-D-One request into the channel); every prompt passes the safety scan (URI schemes via `\b[A-Za-z][A-Za-z0-9+.\-]*:[^\s]` — any ASCII scheme that starts with a letter, followed by a colon then any non-whitespace character; covers `https://`, `file://`, `data:text/plain;...`, `data:,Hello`, `tel:+1-555`, `sms:+1-555`, `magnet:?xt=...`, `javascript:alert(1)`, `mailto:user@...`, `urn:isbn:...`, AND 1-character schemes like `a:b` / `x:malicious-content` / `C:/path` — two earlier regex versions left bypasses: requiring `//` or `[A-Za-z0-9]` after the colon missed schemes followed by `+` / `,` / `?` / `(` / `;`, and requiring at least 2 scheme characters missed `a:b` and Windows-drive `C:/`; absolute Unix `(?:^|\s)/(?:etc|var|usr|home|root|tmp|opt|bin|sbin|dev|proc|sys|System|Library)/`, Windows `[A-Za-z]:[\\/]` (accepts both backslash AND forward slash after the drive letter, since `C:/Windows/System32` is just as valid a Windows path as `C:\Windows\System32`), UNC `\\\\[A-Za-z]`, home `(?:^|\s)~/`, traversal `\.\./` path shapes; raw-source markers `<SOURCE>` / `</SOURCE>` / `[SOURCE]` / `[/SOURCE]` / `raw source` / `begin source` / `end source` / `source document:` / `source text:` / `from the source`; any 40-character substring of `input/source.md` if the source body is present (the scan walks every 40-char alignment of the PROMPT and checks each window for membership in the source — symmetric to "does any 40-char source substring appear in the prompt?" but cheaper when prompts are short, and crucially visits every alignment without skipping); credential shapes JWT `eyJ.+\..+\.`, AWS access key `AKIA[A-Z0-9]{12,20}`, PEM marker `-----BEGIN\s`, long-hex `[a-fA-F0-9]{32,}`, bearer token, and credential literals `password:` / `passwd:` / `secret:` / `api_key:` / `apikey:` / `api-key:` / `token:` / `access_key:` / `client_secret:` / `private_key:`; personal/account shapes email / phone-like / SSN-like / UUID, plus literals `customer_id` / `customer id:` / `account_id` / `account id:` / `acct_id` / `acct id:` / `cust_id` / `user_id` / `user id:`; full-slide / page / screenshot wording `full slide` / `full-slide` / `whole slide` / `entire slide` / `full page` / `full-page` / `whole page` / `entire page` / `full deck` / `whole deck` / `entire deck` / `slide background` / `page background` / `screenshot` / `screen shot` / `screen-shot` / `render the slide` / `render this slide` / `generate the slide` / `generate this slide` / `create the slide` / `create this slide` / `design the slide` / `design this slide` / `render the page` / `render this page` / `generate the page` / `generate this page`); every `requests[].intended_use` (if present) re-runs the full-slide wording subset; `input/source.md` symlink refused; `--plan-out` (defaults to `<workspace>/d_one_adapter_plan.json`) is symlink-refused (leaf-symlink check BEFORE `_resolves_within` so a symlink at the target that points outside the workspace surfaces with the clear "symlink" diagnostic), `local_path_is_safe` against the workspace-relative form, `_resolves_within` against `--workspace`, parent-path segments not symlinks, and not pre-existing as a regular file (no overwrite — caller must remove a prior plan to re-run). Apply / rollback contract: a single deterministic `json.dumps(..., sort_keys=True, indent=2) + "\n"` write to `--plan-out`; on `OSError` mid-write the plan path is unlinked so the workspace returns to its pre-call state. Post-conditions: the plan file re-parses to the in-memory candidate, the just-written plan validates against `schemas/d_one_adapter_plan.schema.json` (strict shape — `additionalProperties: false` at the root and per-request, `schema_version` enum-locked to integer `1`, `mode` enum-locked to `"dry_run"`, `note` must contain the literal `"D-One adapter contract stub"`, `manifest_source` enum-locked to `"d_one_local"`, `request_count` / `width_px` / `height_px` positive integers), and `image_manifest.json` bytes are byte-identical pre/post; a post-condition failure (including a schema-validation failure) unlinks the plan file. Standalone validate-plan mode: `done_image_adapter.py --validate-plan --workspace WS --plan PATH` re-validates an existing `d_one_adapter_plan.json` non-mutatingly — it applies the same string + filesystem gates, the shared `_load_workspace_manifest_and_source` preflight, the plan schema, AND the cross-checks the schema cannot express (`request_count == len(requests)`; no duplicate request ids; every request `id` resolves in the manifest with `source == "d_one_local"`; `manifest_local_path` / `manifest_source` recorded on each request agree with the manifest entry byte-for-byte and re-pass `local_path_is_safe` + `_resolves_within`; every `prompt` re-passes the full URL / file-path / raw-source marker / 40-char source shingle / credential / PII / full-slide wording deny list, and every `intended_use` re-passes the full-slide-wording subset of that list — the same per-field scope `_scan_prompt_safety` and `_scan_intended_use` apply on the write path); the post-condition asserts the manifest bytes and the plan bytes are byte-identical pre/post. The same plan schema can also be checked structurally via the generic scaffold validator `scripts/validate_artifacts.py --schema schemas/d_one_adapter_plan.schema.json plan.json`. Determinism: requests are emitted sorted by `id` so a re-ordered spec produces an identical plan file. When real D-One integration ships, the dry-run plan this stub produces becomes the input to the generator step; D-One's output bytes then flow through `materialize_image_assets.py` for the same magic-byte and path-safety gates that gate any other local asset today. | `image_manifest.materialize` — `scripts/materialize_image_assets.py` is the pre-D-One local image-asset materialization gate. Given a workspace that already ships a schema-valid `image_manifest.json` (typically authored directly or written by the Stage-6 helper `init_image_manifest.py`) plus a `--assets-dir <dir>` of local PNG / JPG / JPEG asset files keyed by `<id>.<ext>` (where `id` matches an `images[].id` in the manifest and `<ext>` is the lower-cased extension of the declared `images[].local_path`), the helper either **copies** the asset bytes into the workspace paths declared by each `images[].local_path` when the target does not yet exist or **verifies** the pre-existing target in place when it does — in both cases the post-condition is that every declared target is a regular non-symlink PNG / JPG / JPEG file whose first bytes match the magic-byte signature for the declared extension. The verify-or-copy semantics support two distinct workflows; `scripts/init_image_manifest.py` itself refuses to overwrite a pre-existing `image_manifest.json`, so the two workflows do NOT chain through it (each stands on its own, and the manifest must already be in place before materialize runs): **direct-author workflow** — the agent writes `<workspace>/image_manifest.json` directly, places asset bytes under `--assets-dir`, then runs materialize (copy branch); `init_image_manifest.py` is NOT invoked in this path; **init_image_manifest workflow** — the agent places asset bytes directly at the declared target paths, runs `init_image_manifest.py` (which requires every declared `local_path` to already resolve to a regular non-symlink file before it writes the manifest), then optionally runs materialize as a verify-only follow-up (defense in depth — `init_image_manifest` does NOT check PNG / JPEG magic bytes). Re-running on a fully-materialized workspace is idempotent. The helper does NOT call D-One / Qoder / any public network / image generation / image search / model API / external service, does NOT open `input/source.md` for business content, does NOT invent prompts, does NOT mutate `image_manifest.json` (manifest bytes must be byte-identical before and after a successful run), does NOT generate full-slide screenshots, and does NOT produce `render_models/*` / `svg_previews/*` / any `.pptx`. Fail-closed gates: `--workspace` and `--assets-dir` each existing directory, not URI-shaped, not itself a symlink; `<workspace>/image_manifest.json` regular non-symlink, parses, decodes to object, schema-validates against `schemas/image_manifest.schema.json`; no duplicate `images[].id`; every `images[].local_path` passes `validate_scaffold.local_path_is_safe`; every lower-cased extension in `{png, jpg, jpeg}`; every target `<workspace>/<local_path>` is not a symlink (leaf-symlink first), no parent path segment is a symlink, resolves inside `--workspace`; **per-image branch: if the target pre-exists it must be a regular non-symlink file whose first bytes match the PNG / JPEG magic signature for the declared extension (verify-only path; no copy); if the target does not exist the source `<assets-dir>/<id>.<ext>` must be a regular non-symlink file whose first bytes match the same signature (copy path)**; every file at the `--assets-dir` root is named by some declared id+ext pair (undeclared assets refused), no subdirectory at the root (the contract is flat), no symlink entries at the root. Apply / rollback contract: the apply loop iterates only over scheduled copy entries (verify-only entries skip the loop entirely — nothing is written for them, and they are not added to the rollback set); each copied target is added to the rollback set BEFORE its `open('wb')` call (half-written file at the failing path is still cleaned up); the apply re-checks magic bytes against the FULL payload (TOCTOU defense); the catch clause is `(Exception, SystemExit)`. Post-condition: `image_manifest.json` bytes byte-identical pre/post; every target a regular non-symlink file matching magic bytes; failure rolls back every target THIS RUN wrote (verify-only entries are not rolled back because the helper did not create them). When real D-One integration ships, it plugs in upstream of this gate; D-One itself remains unimplemented (see `references/d-one-image-policy.md`) | Image manifest | `scripts/materialize_image_assets.py --self-test` (39 in-script tempfixture scenarios) |

- **paraphrase, not quote** — no raw source paragraphs land in `deck_brief` / `deck_plan` / `slide_plan` / `design_system` / `image_manifest`; only short summarized phrasings;
- **sensitive-data handling** — no real customer / account / employee names or sensitive figures appear unless the user explicitly confirmed they are safe (see `references/security-policy.md`);
- **image safety** — `alt_text`, `intended_use`, and any sidecar image prompts carry no raw source text; no slide is a full-slide raster or all-image slide; image assets must already exist locally (D-One image generation is **not** implemented in this repo; see `references/d-one-image-policy.md` for the policy any future integration must satisfy);
- **no automatic prompt/report/Markdown-to-PPTX code** — the agent must not invoke or assume any model API call, public network, telemetry, image generation, Qoder runtime, or other external service; none of those are implemented anywhere in this repo;
- **clean-room discipline** — no content, structure, or wording copied or paraphrased from `ppt-master` (or any similarly named prior implementation; see `references/clean-room-policy.md`).

The machine-checked gates above re-enforce every structural rule the agent's authoring should already satisfy (`brief.bridge.helper`, `plan.count`, `plan.sections`, `plan.section_id`, `plan.slide_source_refs`, `plan.template`, `plan.layouts`, `plan.coverage`, `slide.slots`, `images.path-safety`, `images.exist`, `images.refs`, ...). Running the agent's authoring quality loop first — schema-parse each spec, walk the planner-semantics cross-checks against the deck_plan, confirm slot coverage against the template's per-layout files, confirm every `image_ref` resolves — saves a multi-stage retry against the runtime pipeline. The orchestrators' own up-front gates (`prepare_workspace.orchestration`, `explicit_pipeline.end_to_end`) catch what the agent missed; they do **not** stand in for the agent-managed checks above, since structural validity is not the same thing as source fidelity.

## Reporting

The aggregated report lists, for each gate:

- name;
- status (`pass` / `fail` / `error` / `skipped`);
- artifact identifiers checked;
- repair / mitigation summary if any.

`skipped` is only allowed when the user explicitly skipped a stage; otherwise a missing gate is `error`.
