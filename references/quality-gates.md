# Quality Gates

The gates a deck must pass before the skill reports success. Each gate maps to an explicit stage; if a gate is unimplemented today, that is recorded.

| Gate | Stage | Status |
|---|---|---|
| `source_manifest.bridge` — when `source_manifest.json` is present in the workspace, it must be a **regular in-workspace file**: a symlink at that path (broken or resolvable) is refused outright by an explicit symlink preflight that runs BEFORE `_try_load` / `read_text`, so neither a dangling link silently demoting the workspace to the legacy "no manifest" no-op (Path.is_file() returns False for a dangling target, indistinguishable from a missing file) nor a resolvable link reading manifest bytes from outside the workspace can slip through. The manifest then validates against `schemas/source_manifest.schema.json`; `source.local_path` (enum-locked to `input/source.md`) resolves inside the workspace and exists as a regular file (symlinks at the source file are refused too); the file is valid UTF-8; `source.byte_count` / `line_count` / `sha256` match the on-disk source; and `source.kind` is one of the schema-documented values (`markdown` for a .md-original source, `text` for a .txt-original source — `init_workspace.py` normalizes the on-disk filename to `input/source.md` regardless of the original extension, so both kinds are legitimate). When `deck_brief.json` is present in the same workspace, `deck_brief.source_refs` must include `source_manifest.source.id`. A Stage-1-only workspace (manifest + source.md present, `deck_brief.json` absent) is valid by design: the bridge passes every on-disk row and skips the deck_brief cross-check row rather than emitting a FAIL. Workspaces without `source_manifest.json` are a no-op (existing prepared examples that pre-date `init_workspace.py` remain valid). Tempfixture negatives also cover malformed (non-JSON) and list-rooted manifests as structured loadability / shape FAILs without traceback, and the symlink preflight for both a broken and a resolvable manifest symlink (the dangling target is never created; the resolvable target's bytes are preserved byte-identical and no schema-validate row is emitted because the preflight short-circuits before schema validation runs) | Intake → Brief | scaffold + workspace (`check_source_manifest_bridge` + tempfixture `negative_source_manifest_bridge_tempfixture_checks`) |
| `brief.bridge.helper` — `scripts/init_deck_brief.py` produces a minimal, schema-valid `deck_brief.json` from an already-stage-1-initialized workspace (`source_manifest.json` + `input/source.md`) plus the explicit user-supplied metadata flags (`--title` / `--audience` / `--objective`; optional `--tone` / `--language` / `--approximate-slide-count`). The helper does NOT extract business content from the source body, does NOT invent optional fields the caller did not pass, and does NOT produce any artifact other than `deck_brief.json`. Pre-conditions are enforced by reusing `check_source_manifest_bridge` (so a missing / malformed / sha-mismatched manifest, a missing or wrong-bytes `input/source.md`, or a brief that omits the manifest's `source.id` all fail closed). `source_manifest.json` must be a **regular in-workspace file**: a symlink at that path (broken or resolvable) is refused by an explicit symlink preflight inside the helper that runs BEFORE the is_file check and BEFORE `check_source_manifest_bridge` / `read_text`, so neither a dangling link masquerading as the legacy missing-manifest case nor a resolvable link reading manifest bytes from outside the workspace can slip through; in both cases the helper exits non-zero and no `deck_brief.json` is written. A pre-existing `deck_brief.json` is refused: a **symlink** (broken or resolvable) at that path is rejected outright by an explicit symlink-first guard that runs BEFORE the regular file-existence check, so `write_text()` cannot silently follow a dangling link and clobber whatever the link names (`Path.exists()` returns False for a broken symlink, so a bare existence gate would otherwise let that happen — same anti-pattern `run_pipeline.py` forbids at `--output` / `--report-dir`); a regular file at the same path is refused with the same "no overwrite" rule. `source_refs` is exactly `[source_manifest.source.id]`. The brief is schema-validated in memory before any write and re-validated on disk afterwards; a post-write re-validation failure (returning errors OR raising) rolls the brief back so the workspace returns to its pre-call state. The catch clause is `(Exception, SystemExit)` so `validate_artifact`'s `SystemExit` branch on read-errors still routes through rollback | Brief | `scripts/init_deck_brief.py --self-test` (29 in-script tempfixture scenarios) |

| `image_manifest.materialize` — `scripts/materialize_image_assets.py` is the pre-D-One local image-asset materialization gate. The verify-or-copy semantics support two distinct workflows; `scripts/init_image_manifest.py` itself refuses to overwrite a pre-existing `image_manifest.json`, so the two workflows do NOT chain through it (each stands on its own, and the manifest must already be in place before materialize runs): **direct-author workflow** — the agent writes `<workspace>/image_manifest.json` directly, places asset bytes under `--assets-dir`, then runs materialize (copy branch); `init_image_manifest.py` is NOT invoked in this path; **init_image_manifest workflow** — the agent places asset bytes directly at the declared target paths, runs `init_image_manifest.py` (which requires every declared `local_path` to already resolve to a regular non-symlink file before it writes the manifest), then optionally runs materialize as a verify-only follow-up (defense in depth — `init_image_manifest` does NOT check PNG / JPEG magic bytes). Re-running on a fully-materialized workspace is idempotent. The helper does NOT call D-One / Qoder / any public network / image generation / image search / model API / external service, does NOT open `input/source.md` for business content, does NOT invent prompts, does NOT mutate `image_manifest.json` (manifest bytes must be byte-identical before and after a successful run), does NOT generate full-slide screenshots, and does NOT produce `render_models/*` / `svg_previews/*` / any `.pptx`. Fail-closed gates: `--workspace` and `--assets-dir` each existing directory, not URI-shaped, not itself a symlink; `<workspace>/image_manifest.json` regular non-symlink, parses, decodes to object, schema-validates against `schemas/image_manifest.schema.json`; no duplicate `images[].id`; every `images[].local_path` passes `validate_scaffold.local_path_is_safe`; every lower-cased extension in `{png, jpg, jpeg}`; every target `<workspace>/<local_path>` is not a symlink (leaf-symlink first), no parent path segment is a symlink, resolves inside `--workspace`; **per-image branch: if the target pre-exists it must be a regular non-symlink file whose first bytes match the PNG / JPEG magic signature for the declared extension (verify-only path; no copy); if the target does not exist the source `<assets-dir>/<id>.<ext>` must be a regular non-symlink file whose first bytes match the same signature (copy path)**; every file at the `--assets-dir` root is named by some declared id+ext pair (undeclared assets refused), no subdirectory at the root (the contract is flat), no symlink entries at the root. Apply / rollback contract: the apply loop iterates only over scheduled copy entries (verify-only entries skip the loop entirely — nothing is written for them, and they are not added to the rollback set); each copied target is added to the rollback set BEFORE its `open('wb')` call (half-written file at the failing path is still cleaned up); the apply re-checks magic bytes against the FULL payload (TOCTOU defense); the catch clause is `(Exception, SystemExit)`. Post-condition: `image_manifest.json` bytes byte-identical pre/post; every target a regular non-symlink file matching magic bytes; failure rolls back every target THIS RUN wrote (verify-only entries are not rolled back because the helper did not create them). When real D-One integration ships, it plugs in upstream of this gate; D-One itself remains unimplemented (see `references/d-one-image-policy.md`) | Image manifest | `scripts/materialize_image_assets.py --self-test` (39 in-script tempfixture scenarios) |

| `image_manifest.d_one_live_run_evidence_validator` — `scripts/validate_d_one_live_run_evidence.py <path/to/record.json>` is a **stdlib-only, single-file, NON-mutating local validator** for a future D-One live-run evidence record. Schema-PASS here is a **necessary, not sufficient** precondition — flipping `references/d-one-live-run-readiness.md`'s status from `UNVERIFIED` to `VERIFIED` still requires A19 (re-binding the pinned `plan_sha256` to the actual plan via `scripts/done_image_adapter.py --validate-plan`) plus the `references/d-one-live-integration-design.md` §11 live verification matrix exercised separately. The schema's `minItems` on that array is `0` for exactly this case (an earlier draft of the schema had `minItems: 1`, which made A16 unsatisfiable for fully-failed runs — the schema forced at least one row but A16 required zero; G9 `request_order_sorted_by_id` (A18 — local half) — `requests[]` MUST be lexicographically ascending by `id` (the full A18 check that the order also matches the input plan's order is out of scope here, but the plan is itself sorted by id by `scripts/done_image_adapter.py`, so sorted-by-id in the record is the local-only equivalent); G10 `ok_run_coherence` (readiness §8 PASS overclaim guard) — `run_outcome == "ok"` requires every `requests[*].outcome == "ok"` AND every `per_image_review_refs[*].decision == "pass"`, refusing a top-level PASS claim that hides a rejected request or a FAIL review (per-image FAIL forces the §7 rollback path so the run_outcome would be `rolled_back`, not `ok`); G11 `free_form_field_scan` (A11 + readiness §6 + privacy rules) — defense-in-depth runtime scan over the free-form fields (`note`, `gate_detail`, `evidence_notes`, `endpoint_label`, `operator_label`, `runner_version`, `assets_dir_label`, every `approvals.*_approval_ref`, `operator_ref`, `cleanup_ref`, every `review_ref`, every `requests[*].id` / `manifest_local_path` / optional per-request `endpoint_label`) for credential shapes (JWT, AWS access key, PEM marker, long-hex blob, bearer token, `password:` / `api_key:` / `token:` / `secret:` / `client_secret:` / `private_key:` literals), PII shapes (email, phone-like, SSN-like, UUID, `customer_id` / `account_id` / `user_id` literals), employee-id literals (`employee_id` / `emp_id` / `staff_id` / `badge_id`), internal-endpoint shapes (private IPv4 ranges `10.0.0.0/8` / `127.0.0.0/8` / `192.168.0.0/16` / `172.16.0.0/12`, `*.internal` / `*.local` / `*.corp` / `*.lan` / `*.intranet` TLDs), raw-source markers (`<source>` / `[source]` / `raw source` / `begin source` / `end source` / `source document:` / `source text:` / `from the source`), and public-upload / public-sharing / public-hosting instructions (`upload to public ...` / `public upload` / `share publicly` / `public hosting` / `publish to web` / `public URL`). The public-upload scan exempts safe negated boundary wording such as `no public upload`, `public upload is forbidden`, and `public hosting is not used` so a reviewer can document what the contract refuses without tripping the gate. Negation is recognised only when it sits IMMEDIATELY adjacent to the deny phrase: on the BEFORE side one of `no` / `not` / `never` / `without` followed by whitespace and nothing else; on the AFTER side an optional `is` / `are` / `was` / `were` copula followed by `forbidden` / `prohibited` / `denied` / `disabled` / `blocked` / `refused` / `banned` / `not used` / `not allowed` / `not permitted` / `not enabled`. Intervening words on the BEFORE side are NOT honored (so `no operator approval public upload` fires because the `no` applies to `operator approval`, not to `public upload`); strong verbs in ambiguous surface forms (`forbid public upload`, `refused to share publicly`) are NOT honored as BEFORE-side refusal anchors, only as AFTER-side ones — an earlier draft of the validator allowed intervening words on the BEFORE side plus strong-verb tokens, which created real bypasses; the regression tests at the bottom of `scripts/validate_d_one_live_run_evidence.py --self-test` lock the fix in. ## Pass criteria

The skill may only report `success` when **every** gate above has status `pass`. Gates marked TODO are blockers for end-to-end success — the skill must therefore not yet claim end-to-end success.

A gate marked `error` (the check failed to run cleanly) is **not** a `pass`.

## Pre-pipeline authoring checks (agent-managed)

The gates in the table above are **machine-checked** by the implemented explicit-input runtime pipeline (`init_workspace.py` / `init_deck_brief.py` / `init_deck_plan.py` / `init_design_system.py` / `init_slide_plans.py` / `init_image_manifest.py` / `prepare_workspace.py` / `run_pipeline.py` / `run_explicit_pipeline.py` / `validate_workspace.py` / `validate_pptx_contract.py`). Stage 2-6 spec authoring (filling in `--title` / `--audience` / `--objective` for `init_deck_brief.py`; `--plan-spec` for `init_deck_plan.py`; `--spec` OR `--theme-from-template` for `init_design_system.py`; `--specs-dir` for `init_slide_plans.py`; `--spec` for `init_image_manifest.py`) is **agent-managed** and lives outside that machine surface. The full per-stage authoring contract — including the pre-pipeline quality loop the agent should run before invoking `scripts/run_explicit_pipeline.py` (or the equivalent `prepare_workspace.py` + `run_pipeline.py` split, or the per-stage chain) — lives in the separate document [`authoring-workflow.md`](authoring-workflow.md), so the authoring workflow is never read as runtime code. In particular, the agent owns these checks that no script can perform on its behalf:

- **source fidelity** — every slide title, summary, key point, kpi, and table cell traces to its declared `source_refs`; no fabricated statistics, dates, names, or quotations;
- **paraphrase, not quote** — no raw source paragraphs land in `deck_brief` / `deck_plan` / `slide_plan` / `design_system` / `image_manifest`; only short summarized phrasings;
- **sensitive-data handling** — no real customer / account / employee names or sensitive figures appear unless the user explicitly confirmed they are safe (see `references/security-policy.md`);
- **image safety** — `alt_text`, `intended_use`, and any sidecar image prompts carry no raw source text; no slide is a full-slide raster or all-image slide; image assets must already exist locally (D-One image generation is **not** implemented in this repo; see `references/d-one-image-policy.md` for the policy any future integration must satisfy);
- **no automatic prompt/report/Markdown-to-PPTX code** — the agent must not invoke or assume any model API call, public network, telemetry, image generation, Qoder runtime, or other external service; none of those are implemented anywhere in this repo;
- **clean-room discipline** — no content, structure, or wording copied or paraphrased from `ppt-master` (or any similarly named prior implementation; see `references/clean-room-policy.md`).

The machine-checked gates above re-enforce every structural rule the agent's authoring should already satisfy (`brief.bridge.helper`, `plan.count`, `plan.sections`, `plan.section_id`, `plan.slide_source_refs`, `plan.template`, `plan.layouts`, `plan.coverage`, `slide.slots`, `images.path-safety`, `images.exist`, `images.refs`, ...). Running the agent's authoring quality loop first — schema-parse each spec, walk the planner-semantics cross-checks against the deck_plan, confirm slot coverage against the template's per-layout files, confirm every `image_ref` resolves — saves a multi-stage retry against the runtime pipeline. The orchestrators' own up-front gates (`prepare_workspace.orchestration`, `explicit_pipeline.end_to_end`) catch what the agent missed; they do **not** stand in for the agent-managed checks above, since structural validity is not the same thing as source fidelity.

## Reporting

The aggregated report lists, for each gate:

- name;
- status (`pass` / `fail` / `error` / `skipped`);
- artifact identifiers checked;
- repair / mitigation summary if any.

`skipped` is only allowed when the user explicitly skipped a stage; otherwise a missing gate is `error`.
